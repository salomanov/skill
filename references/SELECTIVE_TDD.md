# Selective TDD by Default (Project Guardian Invariant)

## 16. Selective TDD by Default (Project Guardian v1.7.7)

Правило действует по умолчанию для всех задач, начиная с версии 1.7.7.

### 16.1. Селективность применения

#### 🛡️ Обязательный TDD (тесты пишутся строго ДО кода)
TDD обязателен для любых изменений, затрагивающих проверяемую логику:
- **Бизнес-логика и сервисы** (алгоритмы, валидация, расчеты, структуры данных);
- **Бэкенд и API** (роуты, контроллеры, авторизация, обработка запросов);
- **Telegram-боты** (хэндлеры команд, коллбэки, машины состояний, карточки сообщений, фильтры);
- **Базы данных и ORM** (модели данных, CRUD-операции, миграции);
- **Парсеры и конвертеры** (OPDS, XML, JSON-каталоги, сериализаторы).

#### ⚡ Исключения (TDD не требуется, проверяется фактом)
Без предварительных тестов допустимы изменения, не затрагивающие логику ветвлений и контрактов:
- Конфигурационные файлы (`YAML`, `JSON`, `.env`, `settings.toml`, `uci`);
- Стили и верстка (`CSS`, `QSS`, `HTML-шаблоны`, `Jinja2`-разметка без логики);
- Документация, комментарии и `README.md`;
- Однострочные косметические правки и опечатки;
- Низкоуровневый аппаратный код без виртуальных моков (`GPIO`, `I2C`, `SPI`, `UART`, регистры `ESP32`/`STM32`).

*Если изменение затрагивает одновременно логику и конфигурацию — применяется обязательный TDD.*

### 16.2. Обязательный 3-фазный цикл и раннер `run-tests.ps1`

Все тесты запускаются исключительно через единый стандартизированный раннер:
```powershell
& "C:\Users\Salomanov\.gemini\config\skills\project-guardian\scripts\run-tests.ps1" [-Target <файл_или_папка>]
```
**Инвариант Auto-Ensure Test Runner:**
- Скрипт `run-tests.ps1` автоматически проверяет наличие `pytest`. При отсутствии — сам устанавливает его через `uv pip install --system pytest` (или `pip`).
- Если установка не удалась — скрипт чисто и безопасно запускает встроенный `python -m unittest discover`. Никаких крахов `exit code 1: No module named pytest`!
- Правило Ponytail («не ставь лишние пакеты») **не распространяется** на заявленный разработчиком тест-раннер.

1. **Фаза RED (Красный)**:
   - Создать или дополнить тест в `tests/test_*.py`.
   - Запустить `run-tests.ps1` и зафиксировать падение логики (`AssertionError` / `FAILED`).
2. **Фаза GREEN (Зеленый)**:
   - Написать минимальный рабочий код.
   - Запустить `run-tests.ps1` и получить статус `[TDD GREEN] (exit code 0)`.
3. **Фаза REFACTOR (Рефакторинг)**:
   - Улучшить код, повторно подтвердить `[TDD GREEN]`.

### 16.3. Gate сдачи задачи

**КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** сдавать задачу по бизнес-логике без консольного вывода `run-tests.ps1` со статусом `exit code 0`. Запрещено использовать сырые инлайн-команды `python -c` для тестирования.
