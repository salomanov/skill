# Project Guardian (Универсальный Хранитель Проекта)

Скилл полностью адаптирован под три ключевых направления:
1. 🌐 **Веб-сайты и веб-приложения** (React, Vue, Next.js, HTML/CSS/JS, FastAPI, Flask, Django).
2. 🖥️ **Программы для ПК** (PyQt6/PySide, C# .NET, Electron, Tauri, PyInstaller `.exe`).
3. 🔥 **Прошивки микроконтроллеров** (ARM Cortex, STM32, Teensy, ESP32, Arduino, PlatformIO).

---

## 1. Долговременная память проекта (`PROJECT_STATE.md`)

В корне любого проекта (веб, десктоп или прошивка) ведется файл `PROJECT_STATE.md`:
- **При старте диалога**: агент считывает его и моментально подхватывает контекст (цель, стек, текущее состояние, команды запуска/сборки, открытые задачи).
- **По завершении этапа**: агент актуализирует статус и фиксирует журнал изменений.
- Эталонная структура: [`./references/PROJECT_STATE_TEMPLATE.md`](./references/PROJECT_STATE_TEMPLATE.md).

## 2. Контрольные точки и бэкапы (`checkpoint.ps1`)

Скрипт автоматически распознает тип проекта или принимает категорию явно:
```powershell
# Автоматический чекпоинт кода (перед правками):
& "C:\Users\Salomanov\.gemini\config\skills\project-guardian\scripts\checkpoint.ps1" -Message "Рефакторинг логики"

# Релиз веб-сайта (сохраняет продакшн сборку из dist/build):
& "C:\Users\Salomanov\.gemini\config\skills\project-guardian\scripts\checkpoint.ps1" -Message "Релиз сайта v1.0" -Category "Web" -Release

# Релиз программы для ПК (сохраняет .exe, .msi, библиотеки с SHA256):
& "C:\Users\Salomanov\.gemini\config\skills\project-guardian\scripts\checkpoint.ps1" -Message "Сборка ПК утилиты v1.0" -Category "Desktop" -Release

# Удачная прошивка микроконтроллера (сохраняет .bin, .hex, .elf с SHA256):
& "C:\Users\Salomanov\.gemini\config\skills\project-guardian\scripts\checkpoint.ps1" -Message "Успешный flash v1.2" -Firmware
```

### Принцип «Несгораемых архивов»:
- Каждая сборка/прошивка/релиз сохраняется в **отдельную папку с уникальной датой и временем**:
  - `.backups/firmware_success_YYYY-MM-dd_HH-mm-ss/`
  - `.backups/desktop_release_YYYY-MM-dd_HH-mm-ss/`
  - `.backups/web_release_YYYY-MM-dd_HH-mm-ss/`
- Старые релизы **НИКОГДА не перезаписываются**.
- Создаются паспорта сборки `RELEASE_INFO.md` / `FIRMWARE_INFO.md` с контрольными суммами SHA256 и Git-теги.

## 3. Немедленная фиксация сбоев и ошибок (`record-failure.ps1`)

При любом непредвиденном поведении, зависании ядра, срыве шины (I2C/SPI), ошибках компиляции или аппаратных граблях — агент **ОБЯЗАН немедленно зафиксировать инцидент ДО повторных попыток**:
```powershell
& "C:\Users\Salomanov\.gemini\config\skills\project-guardian\scripts\record-failure.ps1" `
    -Title "Краткое название сбоя" `
    -Symptom "Что сломалось или зависло" `
    -RootCause "Почему это произошло (железо/код)" `
    -Solution "Как исправлено и железное правило"
```
**Что делает скрипт автоматически:**
1. Записывает инцидент в `docs/ERRORS_AND_FAILURES.md`.
2. Автоматически запускает инкрементальное обновление графа знаний `graphify` (`graphify-out/`).
3. Создает защитный бэкап в `.backups/`.
4. Коммитит и пушит в Git `origin`.

## 7. Прагматичный режим Ponytail (Чистый код и экономия токенов)

Агент во всех задачах руководствуется принципом **«ленивого сеньора» (Ponytail)**:
- **Наименьшее полное изменение побеждает**: лучший код — тот, который не пришлось писать. Решать задачу минимальным объемом нового кода.
- **Никакого оверинжиниринга (YAGNI)**: не создавать фабрики, лишние слои абстракций, обертки или функции «на будущее».
- **Максимум стандартной библиотеки**: не ставить сторонние пакеты (`npm`/`pip`), если задача решается стандартными средствами языка или платформы.
- **Переиспользование**: всегда проверять и использовать уже существующие в проекте утилиты и сервисы.
- **Лаконичность ответов**: четкие ответы по существу, экономия контекста диалога.

## 8. Обязательный Security & Reliability Gate (Контроль качества и безопасности)

Перед завершением любой задачи агент обязан провести аудит по 5 ключевым критериям:

1. 🔒 **Защита API и сетевых эндпоинтов (No Open RCE)**:
   - Запрещено оставлять неаутентифицированные эндпоинты, способные выполнять системные команды (`exec`, `shell`, `system`, перезапуск/обновление).
   - Любой сервис, доступный по сети, ОБЯЗАН требовать токен авторизации (`Authorization: Bearer <token>`) или пароль по умолчанию.
   - Запрещено выставлять `Access-Control-Allow-Origin: *` на чувствительные эндпоинты без проверки токена.

2. ⏱️ **Железное правило таймаутов (No Infinite Hangs)**:
   - Каждый вызов `subprocess.run()`, `check_output()`, `curl`, `urllib.request.urlopen()` ОБЯЗАН иметь явный параметр `timeout=...`.
   - Зависшая внешняя команда или обрыв сети никогда не должны блокировать поток или сервер навсегда.

3. 🛡️ **Безопасность Shell-скриптов**:
   - Все сетевые загрузки выполняются СТРОГО через `curl -fsSL` (флаг `-f` обязателен — при ошибке 404 `curl` падает с ненулевым кодом, предотвращая сохранение HTML-ошибки в файл скрипта).
   - Каждый критический шаг установки обязан проверять статус завершения (запрещены безусловные отчеты «Все успешно установлено»).

4. 🔑 **Гигиена секретов и учетных данных**:
   - Запрещен хардкод реальных паролей, закрытых ключей и токенов в `PROJECT_STATE.md`, `README.md` и коммитах.
   - Использовать переменные окружения, защищенные файлы с правами `0600` или шаблоны `.env.example`.

5. ⚡ **Защита ресурсов и памяти (Resource & Memory Guardrails)**:
   - Ограничение размера входящих данных (`Content-Length` не более 64–256 КБ на маломощных роутерах и контроллерах).
   - Кэширование внешних API (например, GitHub API 60 req/hour) для предотвращения выжигания лимитов.
   - Во фронтенде: запрет на использование `innerHTML` для вывода динамических системных данных (использовать `textContent` или санитизацию для защиты от XSS).

## 9. Предотвращение частых сбоев команд (Zero Exit Code 1 Discipline)

Анализ 140+ ошибок `exited with code 1` в сессиях выявил 5 главных системных причин, которые агент ОБЯЗАН исключить:

### 1. Запрет на сложные инлайн-команды в PowerShell (PowerShell Quote, Pipe & Dollar Mangling)
* **Причина сбоев:** При вызове `python -c "..."` через PowerShell символы `$`, `"`, `'`, `|`, `&&`, `$()` и `2>/dev/null` перехватываются самим PowerShell до передачи в Python.
  - Символ пайпа `|` (например `grep -E "a|b"`) воспринимается как пайплайн самого PowerShell, разрывая вызов Python и приводя к ошибке `CommandNotFoundException: Не удается загрузить модуль "..."`.
  - Экранированные кавычки ломаются, переменные с `$` раскрываются в пустоту.
* **Железное правило:** **НИКАКИХ однострочников в `python -c "..."`** при наличии пайпов, кавычек или логики более 1 строки.
  - **ВСЕГДА** создавайте изолированный `.py` скрипт в `scratch/` или `$env:TEMP` и запускайте `python path/to/script.py`.

### 2. Защита от краха кодировки Windows (CP1251 UnicodeEncodeError)
* **Причина сбоев:** В русскоязычной Windows PowerShell использует консольную кодировку `CP1251`. При попытке Python напечатать эмодзи (`👉`, `🔒`), типографские символы, псевдографику или спецсимволы команда мгновенно падает с `UnicodeEncodeError: 'charmap' codec can't encode character`.
* **Железное правило:** В любых вспомогательных Python-скриптах в первой же строке указывать:
  ```python
  import sys
  if hasattr(sys.stdout, 'reconfigure'):
      sys.stdout.reconfigure(encoding='utf-8')
  ```
  Либо устанавливать `$env:PYTHONIOENCODING='utf-8'` перед вызовом Python.

### 3. Запрет на вызов несуществующих Linux-утилит в Windows
* **Причина сбоев:** Попытка вызвать в PowerShell программы из Linux (`grep`, `sed`, `awk`, `ip`, `plink`, `sshpass`), которых нет в Windows PATH.
* **Железное правило:**
  - В Windows использовать встроенные командлеты PowerShell (`Select-String`, `Get-Content`, `Test-Path`).
  - Для работы с SSH/роутером использовать библиотеку `paramiko` внутри `.py` скрипта, а не угадывать CLI-утилиты (`plink`/`sshpass`).

### 4. Ограничения Dropbear SSH: отсутствие SFTP Subsystem
* **Причина сбоев:** В роутерах и встраиваемых системах с Dropbear (Entware, Keenetic, OpenWrt) по умолчанию не установлен `openssh-sftp-server`. Вызов `client.open_sftp()` завершается ошибкой `OSError: Socket is closed` с кодом 1.
* **Железное правило:**
  - Не полагаться на `open_sftp()`.
  - Передавать файлы на роутер через стандартный поток ввода SSH:
    ```python
    stdin, stdout, stderr = client.exec_command(f"cat > {remote_path}")
    stdin.write(file_bytes)
    stdin.close()
    ```
    Этот способ гарантированно работает на любых минималистичных прошивках без внешних зависимостей.

### 5. Git Push & Non-Fast-Forward
* **Причина сбоев:** `git push` падает с `[rejected] non-fast-forward`, если локальная ветка отстает от удаленной (например, при правках в двух репозиториях).
* **Железное правило:** Перед коммитом и пушем всегда выполнять `git pull --rebase` или проверять синхронизацию веток.
