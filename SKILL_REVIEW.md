## Вердикт

Скилл хорош как «память проекта» (чекпоинты, откат, фиксация сбоев, граф), но как **защита от ошибок агента —
нет**. Раздел 8 «Security & Reliability Gate» появился после моего прошлого ревью и содержит правильные
требования — и всё равно агент в этом же проекте:

- добавил хардкод-бэкдор `admin/Salomanov` в `verify_credentials()`;
- отключил авторизацию nfqws-панели (`auth.enabled = false`);
- сделал root-shell на порту 7681 без аутентификации;
- оставил `curl -fsSL … | sh` с ложным «успехом»;
- внёс дедлок на логауте.

Причина не в том, что правил мало, а в том, что **правила декларативные**: нет ни одного исполняемого шага,
который бы их проверил. Агент читает чеклист, ставит галочки «на глаз» и коммитит.

Ниже — что менять по приоритету.

## 1. Критично: убрать разрешение на «пароль по умолчанию»

`SKILL.md:128`:
> Любой сервис, доступный по сети, ОБЯЗАН требовать токен авторизации (`Authorization: Bearer <token>`)
> **или пароль по умолчанию**.

Именно эта формулировка легализовала `admin:Salomanov` в публичном репозитории. Заменить на:

```markdown
- Аутентификация строится ТОЛЬКО на секрете, сгенерированном при установке
  (`secrets.token_urlsafe(12)`, `openssl rand -base64 12`) и показанном пользователю один раз.
- Запрещено: пароли/токены по умолчанию в коде, README, PROJECT_STATE, UI-подсказках и баннерах установки.
- Запрещён любой «аварийный fallback» в проверке учётных данных
  (`if user == "admin" and pass == "<константа>"`). Fallback в аутентификации = бэкдор.
- Публичный репозиторий считается скомпрометированным: любой секрет, попавший в git, считается утраченным.
- Первый вход обязан требовать смены сгенерированного пароля.
```

## 2. Критично: добавить пункт «не отключать защиту ради удобства»

## 3. Критично: добавить чеклист конкурентности (дедлоки)

В скилле нет ни слова про потоки, а именно там сидит фатальный баг (`revoke_session` → `save_sessions` под
тем же `threading.Lock`). Добавить раздел:

```markdown
## Concurrency Gate
- `threading.Lock` не реентрантный: запрещено вызывать функцию, берущую тот же лок, пока лок удерживается
  (`with LOCK: helper()` где `helper` тоже `with LOCK`) — это вечный дедлок.
- Публичные функции с локом не должны вызывать друг друга; сохранение на диск/сеть — только ВНЕ лока.
- Для серверных хэндлеров обязателен smoke-тест «вход → логаут → следующий запрос» и «2 параллельных запроса».
- Любой `daemon_threads = True` сервер обязан иметь лимит одновременных запросов.
```

## 4. Критично: запретить `| sh` и требовать проверяемый код возврата

`SKILL.md:136` требует `curl -fsSL`, но не запрещает пайплайн, а статус пайплайна берётся по последней
команде (`sh`), поэтому сбой загрузки не виден. Добавить:

```markdown
- Запрещено `curl … | sh` и `wget … | sh`: статус пайплайна принадлежит `sh`, ошибка загрузки теряется
  (`shellcheck SC2312`). Только: `curl -fsSL -o "$tmp" "$url" || die; [ -s "$tmp" ] || die; sh "$tmp"`.
- `set -o pipefail` в BusyBox ash отсутствует — на него не рассчитывать.
- Каждый шаг установки возвращает код; итоговое «всё установлено» печатается только при нулевом коде всех шагов.
```


## 7. Заменить «декларативный гейт» на исполняемый скрипт

Раздел 8 — проза. Нужен `scripts/security-gate.ps1`, который агент обязан запускать перед коммитом и который
**валит сборку**. Минимальный набор проверок:

```powershell
# 1) секреты в репозитории
git grep -nE 'Salomanov|password\s*=\s*"|secret\s*=\s*"|BEGIN (RSA|OPENSSH) PRIVATE KEY'
# 2) синтаксис
python -m py_compile router_api.py opkg_update.py ; node --check app.js ; sh -n install*.sh
# 3) shellcheck (если есть)
shellcheck -s sh install*.sh
# 4) антипаттерны
git grep -nE '\|\s*sh\b' -- '*.sh'                 # пайплайн в установку
git grep -nE 'auth\.enabled\s*=\s*false|verify\s*=\s*False' 
git grep -nE 'shell\s*=\s*True' -- '*.py'           # требует обоснования в отчёте
# 5) smoke-тест API: login -> status -> logout -> status(401)
```

Скрипт должен возвращать ненулевой код при любом срабатывании. Без этого раздел 8 останется пожеланием.
